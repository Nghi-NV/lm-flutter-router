Stable preview API

Flutter routing that owns pages, sheets, tabs, links, and back.

`lm_flutter_router` provides a custom `RouterDelegate` engine with typed route definitions, guarded navigation, browser/deep-link support, iOS-style transitions, router-owned modals, and adaptive split views. The common API is intentionally small: start with `Lm.router`, `Lm.page`, `Lm.sheet`, `Lm.guard`, and `context.lm`.

Start With Code Public API Reference Production Recipes

Install

Add the package to your Flutter app:

dependencies:
  lm_flutter_router: ^0.0.1

Import the stable preview API in app code:

import 'package:lm_flutter_router/lm_flutter_router.dart';
Advanced import: use lm_flutter_router_advanced.dart only when building custom framework integrations around the delegate, matcher, state nodes, or page factory.

Quick Start

`Lm.platformRouter` reads the current browser/platform route automatically. `router.scopedBuilder()` exposes `context.lm` to the app. 

import 'package:flutter/material.dart';
import 'package:lm_flutter_router/lm_flutter_router.dart';

void main() {
  WidgetsFlutterBinding.ensureInitialized();

  final router = Lm.platformRouter(
    routes: [
      Lm.page<void>(
        path: '/',
        build: (context, _) => const Text('Home'),
      ),
      Lm.page<int>(
        path: '/orders/:orderId',
        decode: (params) => Lm.params(params).requiredInt('orderId'),
        buildPath: (orderId) => '/orders/$orderId',
        build: (context, orderId) => Text('Order $orderId'),
      ),
    ],
  );

  runApp(
    MaterialApp.router(
      routerConfig: router.config,
      builder: router.scopedBuilder(),
    ),
  );
}

API Cheat Sheet

Setup

Lm.router, Lm.platformRouter, and router.scopedBuilder() cover normal app wiring.

Routes

Lm.page defines pages. Use decode and buildPath when the route has typed params.

Navigation

Use context.lm.go, push, replace, present, and pop.

Modals

Lm.dialog, Lm.sheet, Lm.actionSheet, Lm.fullscreenDialog, and Lm.popover make modals route-aware.

Links

Lm.links maps external or legacy URLs into internal paths. Existing app paths need no setup.

Guards

Lm.guard handles simple auth checks without forcing a custom guard class.

Task Use
Create router from the current URL Lm.platformRouter(routes: [...])
Expose context navigation builder: router.scopedBuilder()
Open a page context.lm.push('/orders/42')
Open a router-owned modal context.lm.present('/orders/42/actions')
Decode an int path param Lm.params(params).requiredInt('orderId')
Build a canonical location Lm.path('/orders', query: {'tab': 'open'})

Routes

Route names are optional. By default the router derives names from paths, so app code can stay path-first and concise. 

final orderRoute = Lm.page<int>(
  path: '/orders/:orderId',
  decode: (params) => Lm.params(params).requiredInt('orderId'),
  buildPath: (orderId) => '/orders/$orderId',
  build: (context, orderId) => OrderDetailScreen(orderId: orderId!),
);

context.lm.push(orderRoute.location(1042));
Use plain strings for simple navigation and route `.location(...)` when you want path construction colocated with the route declaration.

Router-Owned Modals

Declare modals in `modalRoutes` when sheets, action sheets, dialogs, or fullscreen dialogs need deep-link, browser-history, restoration, and system-back support. 

final orderActionsRoute = Lm.actionSheet<int>(
  path: '/orders/:orderId/actions',
  decode: (params) => Lm.params(params).requiredInt('orderId'),
  buildPath: (orderId) => '/orders/$orderId/actions',
  build: (context, orderId) => OrderActionsSheet(orderId: orderId!),
);

final router = Lm.router(
  routes: routes,
  modalRoutes: [orderActionsRoute],
);

Use context.lm.present(orderActionsRoute.location(1042)) to open it. Browser back and system back dismiss the modal before popping page routes.

Deep Links

If incoming URLs already match app paths, no deep-link config is needed. Use `Lm.links` for external domains, old URL formats, or reusable feature-level mappings. 

final router = Lm.router(
  linkTransformers: [
    Lm.links(
      normalize: (uri) => uri.host == 'field-orders.example'
          ? Lm.path('/orders/${uri.pathSegments.last}')
          : null,
    ),
  ],
  routes: routes,
);

Guards

Guards can allow, block, or redirect. `LmGuardRedirect.toLogin` writes the attempted destination to `?returnTo=...`, so the login page can resume after authentication. 

final router = Lm.router(
  guards: [
    Lm.guard((context) {
      final protected = context.transaction.to.path.startsWith('/orders/');
      if (!protected || session.isSignedIn) {
        return const LmGuardAllow();
      }
      return LmGuardRedirect.toLogin('/login', context);
    }),
  ],
  refreshListenable: session,
  routes: routes,
);

Adaptive Layout

Keep one semantic route stack and let layout widgets project it into a compact stack, medium shell, or expanded split view. 

LmAdaptiveRouterSplitView(
  router: router,
  primaryPane: const OrdersListPane(),
  emptySecondary: const EmptyDetailPane(),
  child: child,
);

Use LmDetailPolicy.secondaryPaneOnExpanded on detail routes that should render in the secondary pane on larger screens.

Cross-branch navigation: path navigation owns branch selection. Calling context.lm.go('/settings') from /orders/42 switches the active branch to settings and preserves the orders stack. Use context.lm.switchBranch('orders') only for a pure tab/menu switch that restores the destination branch's existing stack. 
// Open a specific route in another branch.
await context.lm.go('/orders/1042');

// Switch branch without changing that branch's stack.
context.lm.switchBranch('orders');

iOS-Style Transitions And Sheets

Page Transitions

Use LmTransition.cupertino() for iOS push/pop with edge-swipe progress tracking, or LmTransition.none() for tab roots.

iOS 15 Sheet Page

LmTransition.cupertinoSheet() and LmCupertinoSheetNavigator.bound support stacked sheet pages, rounded surfaces, scaled background pages, and nested sheet deep links.

final sheetConfig = LmCupertinoSheetNestedConfig(
  sheetPath: '/lab/cupertino-sheet',
  rootPage: LmCupertinoSheetPage(
    id: 'root',
    path: '/lab/cupertino-sheet',
    builder: (context, navigation) => SheetHome(navigation: navigation),
  ),
  pages: [
    LmCupertinoSheetPage(
      id: 'nested',
      path: '/lab/cupertino-sheet/nested',
      builder: (context, navigation) => SheetNested(navigation: navigation),
    ),
  ],
);
